# Spec: Explicit launcher state
Objective: name the launcher's state machines in one pure module so the UI, tests and UI Automation clients read the same rules. The state module itself adds no feature, screen, network, file or game behaviour.
Scope: DeckState.cs holds the screen table (11 ids: Home, Scaling, Library, Downloads, Music, Settings, Advanced, Saves, Preflight, Help, Setup; Settings is the screen of game settings and Advanced, shown as Advanced Settings, is the feature catalog, since 2026-11-20 on the developer's word; Workshop and Gallery were removed on 2026-11-19 on the developer's word), headings and navigation labels (Downloads is shown as Updates), which screens show the library and the lower transport, which screens open the Feature Deck and at which category, and the music, news and setup phases. Program.cs and DeckAudio.cs (music flags) still store the underlying fields; DeckState only reads them.
Phases: music = empty, loading, playing, paused, stopped, failed. News = unconfigured, config-error, idle, checking, updated, failed. Setup = closed, choose-target, select-files, review, blocked. Update (2026-11-16) = off, idle, checking, current, available, unreachable, untrusted, downloading, ready, install-failed; Updater.cs does the work and SPEC-updater.md defines it. Play (2026-11-16) = unavailable (a game with no native program), needs-setup, ready, running, failed; GameRuntime.cs does the work and SPEC-play.md defines it.
Published snapshot: the window (AutomationId FlutterDeck) carries a UI Automation ItemStatus string, republished only when it changes, for example
`screen=Library;game=1;music=playing;tracks=3;repeat=on;shuffle=off;muted=off;news=unconfigured;unread=2;scaling=stopped;setup=closed;play=needs-setup;text=100;update=idle`
It carries enumerated tokens and counts only: never paths, file names, track titles, window titles or the feed address. An unknown screen is reported as `unknown`. Help shows the same tokens, separated by spaces instead of semicolons, as they were when the page opened.
Stable automation ids: `nav-<screen id>` on navigation buttons, `music-<symbol>` on transport buttons, `screen-heading` on the page heading.
Navigation: Navigate ignores any name that is not in the screen table. check-state.ps1 therefore requires every literal Navigate target and navigation entry in Program.cs to be in the table.
Structure: DeckState.cs pure logic (no WPF, file, network or audio access; compiles alone), DeckStatePureTest.cs rules for the screen table, routes, all music flag combinations, setup phases and snapshot shape, check-state.ps1 compile, purity and source guards.
Command: powershell -NoProfile -File .\check-state.ps1
Left implicit on purpose: scaling surface and capture worker, resize ghost, catalog paging and filters, reference readiness strings, and the Escape handler.
Verified: the module's tests and source guards pass, and the snapshot was read through UI Automation from a running launcher. Not verified: news, scaling and setup phases other than the startup ones were never observed live; no screen reader was run.
